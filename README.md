# بوت القاموس القبطي البحيري

بوت Telegram يبحث في القاموس المرفق (16,297 سجلًا) بالقبطية واليونانية والنطق والإنجليزية والعربية. المستودع **خاص** لأن بيانات القاموس مرفقة.

## الاستضافة المجانية المقترحة

استخدمت **Cloudflare Workers** بدل جلسة polling دائمة: Telegram يرسل كل تحديث إلى Worker عبر HTTPS webhook، فلا نحتاج خادمًا يعمل بلا توقف. توفر الخطة المجانية حاليًا حتى **100,000 طلب يوميًا** و10 ms من CPU لكل طلب؛ هذه حدود استخدام وليست ضمان توفر/اتفاقية خدمة، وقد تتغير.

مصادر رسمية: [أسعار Workers](https://www.cloudflare.com/plans/) و[حدود المنصة](https://developers.cloudflare.com/workers/platform/limits/). خيار Oracle Always Free يوفر VM مجانية بلا مدة محددة، لكنه يطلب بطاقة للتحقق ويمكن استرداد الآلات قليلة الاستخدام؛ لذلك لم أختره لهذا المشروع.

## ما تدعمه نسخة Cloudflare

- `/start` و`/help` و`/stats`.
- `/keyboard` (أو `/kbd` / `/k`): لوحة مفاتيح قبطية مدمجة (inline keyboard) لتكوين الكلمة بالضغط على الحروف من غير كيبورد خارجي، مع أزرار مسح وحذف وبحث مباشر.
- بحث نصي عربي/قبطي/يوناني/إنجليزي، مع تطبيع الحركات العربية وبعض اختلافات الألف والياء.
- صفحات نتائج بأزرار السابق/التالي.
- حماية webhook برمز Telegram السري.
- للأدمن: تسجيل النطق الحقيقي كلمةً كلمةً من داخل Telegram عبر `/record`؛ يحفظ Worker `file_id` الأصلي من Telegram، ثم يعيد إرسال نفس التسجيل للمستخدمين عند ظهور الكلمة.
- الكلمات غير المسجلة تستخدم صوت **Miguel [US Spanish]** من Amazon Polly مع نطق IPA، والملفات المنشورة في فرع `audio` هي نفسها التي يرسلها البوت.
- للأدمن: `/broadcast` ينسخ النصوص والصور والفيديو وVoice والملفات والاستبيانات ومعظم أنواع الرسائل التي يدعم Telegram نسخها؛ يطلب تأكيدًا قبل الإرسال، يبطئ الدفعات احترامًا لحدود Telegram، ويعرض تقريرًا بالأسباب عند تعذر التسليم. إذا تعذّر نسخ الاستبيان يعيد إنشاءه كاستبيان جديد، ولا تنتقل الأصوات السابقة.
- صور بطاقات الكلمات والكابشن أسفل رسائل Voice موقوفة حاليًا؛ تظهر نتيجة البحث كنص ثم Voice فقط.

**قيود الاستضافة المجانية:** هذه النسخة لا تنشئ صور Chromium ولا تحوّل الرسائل الصوتية الواردة إلى نص. يمكن للأدمن تسجيل ملفات Voice أصلية من Telegram وحفظها وإعادة إرسالها؛ والكلمات التي لا تملك تسجيلًا تستخدم ملفات Miguel المسبقة من فرع `audio`. وظائف الصور والتحويل الصوتي المتقدم موجودة في نسخة Python الأصلية (`bot.py`) وتحتاج خادمًا دائمًا وأدوات نظام إضافية. والبحث هنا بنفس أسلوب بوت Apps Script القديم: الكلمة المطابقة تظهر مباشرة (ومعانيها الأخرى خلف زر واحد، كل معنى مرة)، وإلا تظهر كلمات فريدة تبدأ بما كتبته كأزرار.

## النشر التلقائي من GitHub

المستودع العام: [abr429701-oss/coptic-dictionary-bot](https://github.com/abr429701-oss/coptic-dictionary-bot). ملفات النشر موجودة في `.github/workflows/deploy.yml`.

1. أنشئ API Token من [صفحة Cloudflare API Tokens](https://dash.cloudflare.com/profile/api-tokens) بصلاحية **Edit Cloudflare Workers** للحساب المطلوب، وفعّل عنوان `workers.dev` للحساب مرة واحدة. خذ `Account ID` من لوحة Cloudflare.
2. افتح [صفحة أسرار GitHub Actions للمستودع](https://github.com/abr429701-oss/coptic-dictionary-bot/settings/secrets/actions) وأضف:
   - `CLOUDFLARE_API_TOKEN` — التوكن المحدود لـ Workers.
   - `TELEGRAM_BOT_TOKEN` — توكين البوت من BotFather.
   - `APPS_SCRIPT_URL` — رابط Web App المنشور في Apps Script، ويجب أن ينتهي بـ `/exec`؛ مطلوب لتفعيل أرشفة التسجيلات الصوتية.
3. من تبويب **Variables** في صفحة الإعدادات نفسها أضف `CLOUDFLARE_ACCOUNT_ID` بمعرّف الحساب.
4. بعد إضافة `APPS_SCRIPT_URL` أو تغييره، شغّل GitHub Actions → **Deploy Coptic Dictionary Bot** → **Run workflow** مع `setup_webhook=false` لتحديث Worker دون إعادة ضبط webhook. يدفع الـ workflow قيمة السر إلى Worker؛ ثم استخدم `/drive` في البوت للتحقق، و`/syncdrive` لرفع التسجيلات المعلقة. عند النشر الأول الذي يحتاج إعداد webhook اترك `setup_webhook=true`.
5. الرابط الذي يُدخل عبر `/setdrive <الرابط>` يتقدّم على سرّ Worker. استخدم `/setdrive reset` لحذف هذا التجاوز والعودة إلى `APPS_SCRIPT_URL`.
6. سيُنشر Worker تلقائيًا عند كل Push إلى `main` بعد نجاح الاختبارات، ولا يحتاج إلى تشغيل يدوي أو متغير تفعيل إضافي.

### توليد صوت Miguel من IPA Reader عبر GitHub Actions

يستخدم workflow باسم **Build word audio (IPA Reader Miguel)** موقع `ipa-reader.com` نفسه: يفتح الصفحة بمتصفح Chromium، يختار `Miguel [US Spanish]`، يرسل IPA، ثم ينزّل ملف الصوت الذي يعيده الموقع. لا يحتاج هذا المسار إلى AWS credentials أو Google TTS أو مفتاح مدفوع من حسابك.

```xml
<phoneme alphabet="ipa" ph="..."></phoneme>
```

ينتج workflow ملفات OGG/Opus في فرع `audio`، ويحدّث `data/audio-manifest.json` ثم يرسل الروابط إلى `dictionary!L` مع أولوية التسجيل البشري الموجود في `upload!C`. يرسل الطلبات بتشغيل متسلسل وفاصل زمني لتقليل الضغط على IPA Reader؛ وقد يفرض الموقع حدًا أو يمنع الطلبات الكثيفة، لأن الخدمة المجانية ليست API مضمونًا للتوليد الجماعي.

أسرار GitHub مشفّرة ولا تظهر لي. لا ترسل التوكنات في المحادثة ولا تضعها في الملفات. عنوان Worker وسرّ webhook يُنشآن تلقائيًا.

## تسجيل النطق الحقيقي من Telegram

الأدمن المحدد في `ADMIN_CHAT_ID` أو المعرّف الافتراضي يستطيع إرسال `/record` في محادثة خاصة مع البوت. سيعرض البوت كلمة واحدة، ثم:

1. سجّلها من زر الميكروفون في Telegram كرسالة **Voice**.
2. يحفظ البوت `file_id` الأصلي للتسجيل في Durable Object، ولا يرفع ملفًا صوتيًا جديدًا.
3. يعرض الكلمة التالية تلقائيًا.
4. أرسل `/record_stop` للإيقاف، ثم `/record` للاستكمال من أول كلمة لم تُسجّل.

عند بحث أي مستخدم عن كلمة لها تسجيل محفوظ، يرسل البوت نفس رسالة الصوت الأصلية عبر Telegram من دون Caption. الكلمات غير المسجلة تستخدم صوت Miguel من فرع `audio`. لا يوجد مسار Google TTS احتياطي حتى لا يختلف الصوت بين البوت وملفات GitHub.

## أمان التوكن

إذا سبق مشاركة توكين Telegram في محادثة أو مستودع أو سجل بناء، ألغِه من `@BotFather` عبر `/revoke`، ثم أضف التوكن البديل إلى GitHub Actions Secrets فقط. لا ترسله في الرسائل.

## مزامنة القاموس من Google Sheets

مصدر البيانات الآن هو [الشيت الجديد](https://docs.google.com/spreadsheets/d/14pUNXtrHoMSU9lBWhKQZyspe-DDTMDudSiuL2sJQRUI/edit) (`SHEET_ID` داخل `scripts/sheet_to_json.py`). ترتيب الأعمدة: A قبطي، B IPA، C عربي، D إنجليزي، E فرنسي، F ألماني، G يوناني، J الأصل، K النوع. يعمل GitHub Actions كل 30 دقيقة: ينزّل الشيت كـ CSV ويحوّله إلى `data/dictionary.json`، وإذا تغيّرت البيانات يحفظها وينشر الـ Worker تلقائيًا. يدعم البوت الآن البحث بالكلمات اليونانية من العمود G، مع البحث السابق بالقبطية والعربية والإنجليزية والفرنسية والألمانية. لا يتغيّر شيء في الـ Worker نفسه أثناء الطلبات، فلا تتأثر حدود الاستخدام ولا السرعة. تشغيل يدوي: Actions ← Deploy Coptic Dictionary Bot ← Run workflow.

## البحث من أي محادثة (Inline) وعدّاد الطلبات

- **Inline:** فعّله مرة واحدة من @BotFather ← `/setinline` ← اختر البوت ← اكتب نصًا مثل «اكتب كلمة قبطية أو عربية». بعدها في أي محادثة اكتب `@اسم_البوت كلمة` واختر النتيجة لتُرسل. (يتطلب `inline_query` في `allowed_updates`، وهو مضاف في الـ workflow و`/__setup`.) نتائج الصوت تستخدم رابط ملف Miguel المباشر من فرع `audio`.
- **`/usage` (للأدمن):** يعرض طلبات اليوم من 100,000، والمتبقي، ووقت التصفير بتوقيت القاهرة، وآخر 7 أيام. وينبّه الأدمن تلقائيًا عند 50% و80% و95% و100%. العدّاد تقديري (كتابة مجمّعة كل ~20 طلبًا).

**ملاحظات Inline:** نص البلاس هولدر يُضبط من @BotFather ← `/setinline` فقط. الكلمات المسجّلة بـ `/record` تُرسل كفويس؛ وغيرها تستخدم ملف Miguel من فرع `audio`. للتشخيص أرسل `/botinfo` للأدمن.

## كروت الكلمات (صور)

`scripts/render_cards.mjs` يرسم كارتًا `cards/<id>.png` لكل كلمة مسجّلة صوتيًا (لها رابط في ورقة upload) بتصميم `scripts/card.mjs`، ويحدّث `data/cards.json` ({id: hash}). يُرسَم فقط ما تغيّر. الـ QR داخل الكارت يفتح تسجيل النطق على Drive. يرسل البوت الكارت كصورة والشرح كتعليق، ويحفظ `file_id` من تيليجرام فتكون الإرسالات التالية فورية. لرسم كل الكلمات (QR يفتح البوت): `CARD_SCOPE=all`. لاستخدام خط قبطي آخر ضع الملف في `fonts/coptic-card.ttf`. عند تغيير التصميم ارفع `CARD_VERSION` في `render_cards.mjs`.

## مزامنة التسجيلات وحذفها

- `/syncdrive` يفحص Drive وورقة `upload` في الاتجاهين، يزيل التسجيلات المحذوفة، ثم يرفع التسجيلات القديمة المعلقة على دفعات.
- `/voice_delete كلمة` يحذف تسجيل كلمة من البوت وDrive وورقة `upload`.
- `/voice_delete_many كلمة1|كلمة2` لحذف مجموعة، و`/voice_delete_all` لحذف كل التسجيلات بعد التأكيد.
- اسم ملف Drive يُؤخذ من صف الكلمة في `dictionary` بصيغة العربي الكامل ثم القبطي، بينما العمود الثاني في `upload` يكتب القبطي فقط.
- `/syncusers` يرحّل المستخدمين القدامى إلى ورقة `users` على دفعات، والتسجيل التلقائي مستمر للمستخدمين الجدد.

## الحذف الدفعي وورقة المستخدمين

- `/voice_delete_all` ينفذ حذفًا دفعيًا واحدًا: يحذف كل صفوف `upload` وينقل كل ملفات مجلد الأصوات إلى المهملات، بما فيها الملفات غير الموجودة في الشيت، ثم يمسح التسجيلات المحلية من البوت. المجلد نفسه يبقى فارغًا لاستقبال التسجيلات الجديدة.
- ورقة `users` تستخدم الأعمدة المختصرة: الاسم، username، Telegram ID، `joined_at`، `registered_at`، و`blocked` بقيمة `نعم` أو `لا`.

## التحديثات الجديدة (Pro Features)

### 1) بحث أدمن سريع مع اقتراحات
- أُعيدت كتابة `localDictionaryLookup` لتعيد قائمة مرشحين (`localDictionaryCandidates`): مطابقة **exact** أولاً، ثم **partial** (يحتوي/محتوى)، ثم **fuzzy** بمسافة Levenshtein محدودة على حقول coptic/meaning/english/greek/pronunciation، بأقوى ~8 مرشحين.
- `dictionaryGetFromSheet` أصبح **محليًا أولًا** (فوري في الذاكرة، 17228 سجل): مرشح واحد دقيق يُفتح فورًا دون لمس الشيت؛ عدة مرشحين تُعرض كأزرار inline (كل زر يُظهر الكلمة القبطية + مقتطف المعنى) وعند الضغط يفتح تعديل ذلك الصف عبر `openDictionaryEditByRow`. الشيت يُستدعى فقط كـ fallback عند عدم وجود نتيجة محلية.
- زر **➕ إضافة كلمة جديدة** يظهر مع الاقتراحات وعند عدم وجود نتيجة.

### 2) إضافة كلمة جديدة من واجهة التعديل
- زر «➕ إضافة كلمة جديدة» في صفحة dictionary (`/admin`) يبدأ flow `dict_new` بـ 11 عمودًا فارغًا ونفس واجهة الأعمدة القابلة للتعديل (`dictionaryNewMarkup`) مع زرّي «💾 حفظ وإضافة الصف» و«❌ إلغاء».
- كل ضغطة على عمود تضبط `flow.col` وتُكتب في `flow.values[col]` محليًا (نفس آلية `dict_value`، عبر `updateDictionaryNewField`).
- عند الحفظ يستدعي الإجراء الجديد `dictionary_append` في `apps-script/Code.gs` (يلحق صفًا بنهاية ورقة dictionary ويعيد رقم الصف + القيم)، ثم يُضاف السجل محليًا إلى مصفوفة `records` بمعرّف مؤقت فريد ويُرسل تأكيد برقم الصف.

### 3) قائمة أوامر منظمة في /start
- دالة `buildCommandsHelpText(env, userId)` تعيد نصًا منسقًا مقسمًا لأقسام (عامة / للأدمن فقط شرطيًا إذا كان `isAdmin`). تُرسل كرسالة نصية منفصلة بعد صورة الترحيب (لأن حد caption الصورة 1024 حرف)، في مسارَي `/start` للمستخدم العائد وللمسجل الجديد.

### 4) ست مميزات احترافية كاملة
- **أ. Rate limiting لكل مستخدم**: نافذة انزلاقية في الذاكرة (`checkRateLimit`، 30 طلب/10ث للمستخدمين العاديين، 5× للأدمن)، مع تنبيه مُخفَّض التكرار عند تجاوز الحد.
- **ب. تحليلات الاستخدام**: عدّاد عمليات البحث/الأوامر/inline + أكثر الكلمات بحثًا (`trackUsage`، `analyticsState`)، يُلقى لقطة دورية إلى Durable Object (`analytics:snapshot`). زر «📊 تحليلات البحث» في أدوات النظام وأمر `/analytics` يعرضان التقرير وأعلى 15 كلمة.
- **ج. سجل تدقيق (audit log)**: كل تعديل/إضافة صف في القاموس يُسجَّل (من، متى، أي عمود، قيمة قديمة/جديدة) في `logAudit`، مع لقطة دورية إلى DO. زر «📋 سجل التدقيق» وأمر `/auditlog` يعرضان آخر 30 إدخال.
- **د. تصدير بيانات للأدمن**: زر «📦 تصدير القاموس JSON» و«👥 تصدير المستخدمين CSV» (وأوامر `/export` و`/export users`) يرسلان الملفات مباشرة عبر `sendDocument` (`sendTextFile`).
- **هـ. أمر /random**: يعرض كلمة عشوائية من القاموس مع بطاقتها ونطقها (متاح للجميع).
- **و. نقطة صحية /health JSON**: ترجع `{"status":"ready","records":N,"time":...,"usersStore":bool,"driveConfigured":bool}` للمراقبة (تبقى تحتوي كلمة "ready" للتوافق).
- **ز. نسخة احتياطية /backup**: أمر أدمن يأخذ لقطة فورية من `records` ويرسلها كملف JSON مؤرشف بالتوقيت.
- **ح. تحسين logging**: كل طلب webhook يُسجَّل بمدته ونوعه بشكل منظم (`console.log` JSON بمفاتيح موحدة: `ev`, `kind`, `update_id`, `dur_ms`)، بالإضافة إلى سجل `audit` لكل تعديل قاموس.

## Admin Commands — الدفعة الأولى (13 ميزة)
- **الإذاعة الجماعية /broadcast**: موجودة بالفعل (bcstart في UserStore + alarm بسرعة ~25 msg/sec + تخطي المحظورين + تقرير نهائي) + زر الحالة `ad|bcstatus`.
- **إدارة المستخدمين**: `/users [بحث]` قائمة آخر المستخدمين، `/ban <id> [سبب]`، `/unban <id>`، `/userinfo <id>` (آخر عمليات بحث + تاريخ انضمام). المحظورون يُرفضون في بداية كل رسالة.
- **حذف كلمة /deleteword**: بحث محلي → تأكيد مزدوج → `dictionary_delete` في Code.gs + حذف ناعم محلي (يحفظ السجل كاملًا في audit log).
- **إحصائيات القاموس /dictstats**: الإجمالي، الناقصة صوتًا، التوزيع حسب kind/origin، آخر 10 مضافة.
- **وضع الصيانة /maintenance on|off**: محفوظ في DO؛ المستخدمون العاديون يرون رسالة صيانة، الأدمن يفضل شغال. زر `ad|maintoggle`.
- **محرر الترحيب /editwelcome <نص>** (استخدم `{name}`) و`/resetwelcome` للنص الأصلي؛ محفوظ في DO.
- **إدارة الأدمنية /admins list|add <id>|remove <id>**: أدمن إضافيون في DO يُدمجون مع DEFAULT_ADMIN_IDS (كاش في الذاكرة، `isAdmin` يفحص الاثنين).
- **سجل الأخطاء /errors**: يلتقط الاستثناءات في handleUpdate، آخر 20 خطأ في ذاكرة+DO.
- **كشف المكررات /duplicates**: كلمات بنفس الكلمة القبطية بعد التطبيع، مع أرقام الصفوف.
- **معاينة /preview <كلمة>**: تعرض الكلمة كما يراها المستخدم العادي.
- **إعادة مزامنة قسرية /resync**: يعيد تحميل dictionary.json من GitHub raw ويمسح كاش فهرس البحث.
- **صندوق الاقتراحات**: `/suggest <نص>` عام يحفظ الاقتراح في DO؛ الأدمن يشوفها بـ `/suggestions` مع أزرار موافقة (تضيف تلقائيًا عبر dictionary_append) / رفض.
- **سجل بحث مستخدم /userhistory <id>**: آخر عمليات بحث (ring buffer في ذاكرة + لقطة دورية في DO).

## Admin Commands — الدفعة الثانية (10 ميزات)
- **محرر معلومات البوت**: `/setbotname`، `/setbotabout`، `/setbotdescription` (setMyName/setMyShortDescription/setMyDescription)، `/setcommands`.
- **تعديل جماعي /bulkedit <عمود A-K> <قيمة>**: يملأ الخلايا الفاضية في ذلك العمود (حتى 50 صف) عبر dictionary_update، مع تقرير نجاح/فشل.
- **نقاط ولوحة متصدرين /gamify on|off** + `/leaderboard` (عام): نقاط لكل بحث + سلسلة أيام، محفوظة في DO بلقطة دورية.
- **مفاتيح API /apikey generate|list|revoke <key>** + endpoint عام للقراءة `GET /api/dictionary?key=...&q=...` (JSON، rate limit 120/min لكل مفتاح).
- **تخصيص حدود السرعة /ratelimit <عدد>**: يضبط الحد العام محفوظًا في DO ويقرأه `checkRateLimit`.
- **روابط دعائية /reflinks**: تتبع المستخدمين الجدد من `t.me/bot?start=campaign` (يُحفظ reflink في ملف المستخدم).
- **رفع صوت نطق /uploadaudio <كلمة>**: الأدمن يرسل Voice/audio، البوت ينزله عبر getFile، يحوله base64، ويستدعي إجراء `upload` الموجود في Apps Script.
- **تصدير Anki /exportanki**: CSV بتنسيق Anki (Front=قبطي، Back=المعنى+النطق+الأصل).
- **زر القائمة /setmenubutton default|<url>**: ضبط setChatMenuButton.
- **كشف سبام تلقائي /spamlist**: المستخدمون الذين يتجاوزون rate limit يُعلَمون مشبوهين ويظهرون للأدمن بضغطة زر مع اختصار /ban.

### مميزات استُبعدت عمدًا
- **تحرير مخطط الأعمدة (/addcolumn)**: يغيّر ثوابت DICTIONARY_LOCAL_FIELDS وبنية الشيت — خطر كسر البيانات.
